# 时间计划工作台

一款由我与 AI 协作设计并开发的个人时间管理网页应用，将目标拆解、任务执行、时间记录、进度追踪和周期复盘整合在同一套工作流中。

**在线体验：** [https://sk2999.github.io/time-workbench/](https://sk2999.github.io/time-workbench/)

## 项目背景

在日常学习和工作中，普通计时工具通常只能回答“花了多少时间”，却很难继续回答：这些时间投入到了哪个目标、具体推进了什么任务、目标完成度如何，以及一周或一个月的精力分配是否合理。

因此，我希望制作一个真正适合自己使用的时间工作台，把“做计划”和“记时间”连接起来：先将长期目标拆解为子目标和任务项，再记录每次投入，最终通过时间看板和进度数据完成复盘。

## 核心功能

- **分层目标管理**：按照“项目 / 目标—子目标—任务项”组织计划，并设置重要性、目标数量、计量单位和进度。
- **实时记录**：选择对应项目、子目标和任务项后开始计时，结束时记录本次完成量或推进情况。
- **历史补录**：手动补充已经发生的时间段、任务描述和完成量。
- **进度自动回算**：根据任务记录计算任务项与子目标进度，减少重复维护。
- **多周期时间看板**：通过日、周、月、年视图查看时间分布和投入结构。
- **多种目标类型**：支持普通目标、日常习惯和每日时间上限等不同管理方式。
- **数据迁移**：支持将本地数据导出为 JSON，并在其他浏览器中重新导入。

## 我和 AI 如何协作

这个项目并非由 AI 一次性生成，而是在真实使用过程中经过多轮需求分析、实现、测试和修正逐步形成。

### 我的工作

- 从个人时间管理需求出发，提出产品问题并确定使用场景。
- 设计目标、子目标、任务项和时间记录之间的数据关系。
- 决定功能优先级、交互方式和界面信息结构。
- 在实际使用中测试计时、补录、进度计算和不同周期看板。
- 发现异常情况，描述复现路径，并判断修改结果是否符合需求。
- 对 AI 生成的方案进行取舍、验证和持续迭代。

### AI 的协助

- 将自然语言需求整理为可执行的功能结构和实现步骤。
- 辅助编写与修改 HTML、CSS 和 JavaScript 代码。
- 根据问题现象检查状态管理、时间计算和进度回算逻辑。
- 协助优化响应式布局、表单交互和视觉层级。
- 在每轮修改后辅助检查潜在边界情况和回归风险。

### 协作流程

```text
发现真实问题 → 描述需求与约束 → AI 给出实现方案
      ↑                              ↓
继续使用与迭代 ← 人工验证和判断 ← 生成或修改代码
```


## 代表性迭代

- 从单纯的项目计时，扩展为“项目—子目标—任务项”三级计划结构。
- 将时间记录与完成量关联，使进度能够根据实际记录自动更新。
- 增加日、周、月、年视图，让数据既能支持当天执行，也能用于长期复盘。
- 区分量化目标、主观进度、日常习惯和每日上限，适配不同类型的计划。
- 加入旧版本数据兼容以及 JSON 导入、导出，避免迭代过程中丢失个人记录。

## 技术实现

- 原生 HTML、CSS、JavaScript
- 浏览器 `localStorage` 本地数据持久化
- 响应式页面布局
- 原生日期、时间区间与进度计算
- PWA Web App Manifest
- GitHub Pages 静态部署

项目不依赖前端框架或后端服务，可直接作为静态网页运行。

## 数据与隐私

所有目标和时间记录默认只保存在当前浏览器的 `localStorage` 中，不会上传到服务器或公开仓库。不同访问者拥有相互独立的本地数据。

用户可以通过侧边栏的导入、导出功能自行备份和迁移数据。清除浏览器网站数据前，建议先导出 JSON 备份。

## 本地运行

克隆仓库后，在项目目录执行：

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

然后访问：

```text
http://127.0.0.1:4173/
```

项目没有构建步骤，也可以使用其他静态文件服务器运行。
